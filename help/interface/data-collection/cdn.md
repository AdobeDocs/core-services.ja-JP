# CDNを介したデータ収集のルーティング

一部の企業では、データ収集リクエストをAdobeに直接送信するのではなく、コンテンツ配信ネットワーク（CDN）を通じてルーティングしています。 一般的な理由には、web アプリケーションファイアウォール（WAF）による保護、すべてのweb サイトトラフィックがCDNを通過することを要求する企業ポリシー、Adobeに送信されるトラフィックを検査する機能などがあります。 CDNは、組織が所有するホスト名でリクエストを受け取り、そのリクエストをオリジンと呼ばれるAdobe データ収集ホスト名に転送します。

>[!IMPORTANT]
>
>Adobeは、CDN設定を確認または検証できません。 組織とCDN プロバイダーは、CDNを正しく設定する責任があります。 CDNの設定について詳しくは、CDN プロバイダーにお問い合わせください。 誤って設定されたCDNは、データが失われる可能性があります。

## オリジンの種類を選択 {#origin-type}

| | サードパーティ製オリジン （推奨） | ファーストパーティオリジン |
| --- | --- | --- |
| **オリジンホスト名** | `example.data.adobedc.net`など、`data.adobedc.net`のテナント ID サブドメイン | `data.example.com`などの1st パーティホスト名 |
| **Adobe サーバーの証明書** | Adobeの証明書（`*.data.adobedc.net`） | [顧客管理の証明書](customer-managed-cert.md) |
| **証明書の更新** | なし | 組織は証明書を更新し、有効期限が切れるたびにAdobeに提供します |
| **リージョンロック済み[RDC](rdc.md)** | サポートなし | 対応 |
| **使用するタイミング** | 組織がファーストパーティオリジンを必要としない限り、すべてのCDN実装 | セキュリティポリシーでは、発信元の証明書を直接管理する必要があります。組織では、リージョンロックされたRDC タイプが必要です |

>[!NOTE]
>
>[Adobeが管理する証明書プログラム ](adobe-managed-cert.md)は、CDN実装をサポートしていません。 Adobeでは、CDNを指すホスト名のドメイン所有権を検証したり、証明書を更新したりすることはできません。 サードパーティのオリジン、または[顧客管理の証明書](customer-managed-cert.md)を持つファーストパーティのオリジンを使用します。

## すべてのCDN実装の要件 {#requirements}

AppMeasurementやweb SDKなどのAdobe データ収集ライブラリには、各リクエストにAdobeが必要とするすべてのものが含まれています。 これらのリクエストを変更せずにAdobeに転送するようにCDNを設定します。

>[!IMPORTANT]
>
>レポートスイート ID （AppMeasurement）やデータストリーム ID （Web SDK）など、データの送信先を決定するエンドポイントや何かを変更しないでください。 これらの値を変更すると、データが失われます。

CDN設定は次の必要があります。

* リクエストメソッド、URL パス、クエリ文字列、本文を変更せずに転送します。
* `Host` ヘッダーは変更しないでください。
* Adobe Cookieが設定されているドメインは変更しないでください。
* このガイドの[cookie セクション ](cookies/overview.md)に記載されているすべてのCookieを保持します。
* 訪問者のIP アドレスを含む`X-Forwarded-For` ヘッダーを追加します。 Adobeでは、このヘッダーを位置情報に使用します。 位置情報データがなければ、訪問者ではなくCDNのサーバーの場所が反映されます。
* Adobeのレスポンスを変更なしでブラウザーに返します。

CDN設定では、次のことが可能です。

* サイト上の他のシステムのCookieなど、Adobeで使用されていないCookieを削除します。 無関係なCookieは、すべてのリクエストにオーバーヘッドを追加します。
* 上記の変更がない限り、WAF、ボットフィルタリング、または個人データ削除サービスを使用します。 本番トラフィックに適用する前に、開発レポートスイートまたはデータストリームを使用してこれらのサービスをテストします。 過度に強引なフィルタリングを実行すると、レポートを使用できないほど十分なデータが削除される場合があります。

CDN設定では、次の操作を行う必要があります。

* データ収集のリクエストまたは応答をキャッシュします。 あらゆるリクエストをAdobeに送信する必要があります。
* 存在しないオリジンのホスト名を指定します。
* 期限切れの証明書を受け入れるか、発信元から特定の証明書をピン留めします。 Adobeでは、期限切れの証明書の配信はサポートしておらず、いつでも削除できます。

## サードパーティのオリジンを使用したCDNの設定 {#third-party-origin}

サードパーティのオリジンはAdobe独自の証明書を使用するため、Adobe サーバーで証明書を管理する必要はありません。

1. 組織のテナント IDを検索します。 「[ テナント IDを見つける](collection-domain.md#tenant-id)」を参照してください。
1. CDN設定で、オリジンのホスト名を`data.adobedc.net`のテナント ID サブドメインに設定します。 例：`example.data.adobedc.net`。
1. オリジンのサーバー名表示（SNI）を有効にします。 SNI ホスト名は、web サイトのホスト名ではなく、オリジンのホスト名（例：`example.data.adobedc.net`）に設定します。
1. 上記のすべてのCDN実装](#requirements)の[要件を満たすようにCDNを設定します。
1. 実装が変更にデータを送信するホスト名が変更された場合、[実装を更新します](collection-domain.md#update-implementation)。 同じホスト名を使用している場合は、実装の変更は必要ありません。

>[!WARNING]
>
>AdobeがCNAME ターゲットとして提供した`hiodsibxvip01.data.adobedc.net`などのホスト名にオリジンを設定しないでください。 そのホスト名はファーストパーティ証明書に関連付けられており、証明書が削除されると動作を停止する可能性があります。

サードパーティのオリジンでは、常にデフォルトの[RDC タイプ ](rdc.md)が使用されるため、任意のAdobe データ収集場所でデータを収集できます。

## ファーストパーティオリジンを使用したCDNの設定 {#first-party-origin}

1st パーティオリジンは、組織で必要な場合にのみ使用してください。 一般的な理由は次のとおりです。

* セキュリティポリシーでは、発信元の証明書を直接制御する必要があります。 例えば、組織が独自の認証局を通じて証明書を失効できるようにする必要があります。
* 組織には、地域ロック済みの[RDC タイプ ](rdc.md)が必要です。

1. Adobe カスタマーケアにお問い合わせいただき、`data.example.com`などのファーストパーティホスト名に[ カスタマー管理の証明書](customer-managed-cert.md)を設定してください。 組織でリージョンロックされたRDC タイプが必要な場合は、リクエストで指定します。
1. CDN設定で、オリジンホスト名をファーストパーティホスト名に設定します。
1. オリジンのサーバー名表示（SNI）を有効にします。 SNI ホスト名をファーストパーティのホスト名に設定し、CDNを設定して、発信元からファーストパーティ証明書を期待するようにします。
1. 上記のすべてのCDN実装](#requirements)の[要件を満たすようにCDNを設定します。
1. 実装が変更にデータを送信するホスト名が変更された場合、[実装を更新します](collection-domain.md#update-implementation)。 同じホスト名を使用している場合は、実装の変更は必要ありません。

>[!IMPORTANT]
>
>お客様は、お客様が管理する証明書を更新し、有効期限が切れる前にAdobe カスタマーケアに提供する責任があります。 Adobe サーバー上の証明書の有効期限が切れた場合、CDNはユーザーに通知することなく接続を拒否し、データを破棄できます。 「[証明書を更新する](customer-managed-cert.md#renewals)」を参照してください。

## 既存の1st パーティ実装をCDNに移行する {#migrate}

現在、Adobeでホストされている証明書を使用してファーストパーティホスト名にデータを直接送信している場合は、次の手順に従ってCDNに移行します。

1. Adobeの全製品をまたいで、ファーストパーティホスト名にデータを送信するあらゆる実装を特定します。 Adobe TargetやAdobe Journey Optimizerなどの他の製品では、同じホスト名を使用する場合があり、1つの証明書で多くのホスト名をカバーできます。
1. [origin type](#origin-type)を選択してください。 ファーストパーティのオリジンを選択した場合は、有効期限が切れる前にAdobe カスタマーケアに連絡して、証明書を[ カスタマー管理の証明書](customer-managed-cert.md)に変換してください。
1. CDNを設定します。 実装を更新する必要がないように、既存のホスト名を維持します。
1. 証明書の有効期限が切れる前に、ホスト名をCDNに指定し、すべての実装を切り替えて使用します。
1. [ データを確認](#check)。
1. サードパーティのオリジンを選択した場合は、Adobe カスタマーケアに連絡して、ファーストパーティ証明書を削除するようにマークしてください。

ホスト名がCDNをポイントすると、Adobeは1st パーティ証明書を更新できません。 証明書の有効期限が切れる際に何らかの実装がまだ証明書に依存している場合、その実装のデータは失われます。 Adobe カスタマーケアに連絡すると、証明書が削除されたときに組織が制御できるようになります。

## データの確認 {#check}

AdobeでCDN設定を検証できません。 CDNを介してデータ収集をルーティングした後、変更前と変更後のデータを比較します。

* データは、通常のボリュームで、想定されるレポートスイート、データストリーム、またはデータセットに引き続き届きます。
* 位置情報レポートには、CDNのサーバーが配置されている都市の数ではなく、訪問者の場所が表示されます。
* ユニーク訪問者数が予期せず増加することはありません。
* ブラウザーのデベロッパーツールでは、ホスト名に対するデータ収集リクエストが成功し、Adobe Cookieが以前と同じドメインに設定されます。

## 一般的な設定ミス

データ品質の問題やデータ損失の原因となることが知られている問題は次のとおりです。 このリストは網羅的ではありません。

| 症状 | 考えられる原因 |
| --- | --- |
| レポートスイートまたはデータストリームにデータが届かなくなります | CDNがリクエスト URLを変更するか、オリジン ホスト名が存在しません |
| 証明書の有効期限が切れると、データが届かなくなります | CDNはオリジンからのファーストパーティ証明書を想定しており、その証明書は期限切れです |
| 位置情報では、一部の都市しか表示されません | CDNは`X-Forwarded-For` ヘッダーを追加しません |
| ユニーク訪問者数が予期せず増加 | CDNは、Adobe Cookieを削除するか、`Host` ヘッダーを変更するか、Cookie ドメインを変更します |
| レポートに大量のデータが欠落している | 個人情報の削除またはWAFの規則により、各リクエストが多すぎる場合 |

## よくある質問

+++このページはAdobe Analytics以外の製品に適用されますか？

はい。 このページは、Customer Journey Analytics、Adobe Experience Platform、Adobe Target、Adobe Journey Optimizerなど、Adobe データ収集を使用するすべてのAdobe製品に適用されます。

+++

+++Adobeは、CDNを経由しないデータを拒否できますか？

いいえ。 Adobeでは、現在、データ収集をCDNからのリクエストに制限する方法を提供していません。

+++

+++Adobeは、CDNの設定を提供または検証できますか？

いいえ。 CDNの設定オプションは、プロバイダーによって異なり、時間の経過とともに変化します。 CDNの設定に関するヘルプについては、CDN プロバイダーにお問い合わせください。設定に関する問題を特定する方法については、[ データの確認](#check)を参照してください。
