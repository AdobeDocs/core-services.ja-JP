# 顧客管理の証明書

お客様が管理する証明書を使用すると、ファーストパーティデータ収集ホスト名の証明書が取得され、Adobeに提供されます。 Adobeは、そのデータコレクションサーバー上で証明書をホストします。 お客様の組織は、現在の証明書が期限切れになる前に、証明書を更新し、更新された各証明書をAdobeに提供する責任があります。

>[!TIP]
>
>Adobeでは、ほとんどのファーストパーティ実装に対して[Adobeが管理する証明書プログラム ](adobe-managed-cert.md)を推奨しています。 より安全で、証明書を自動的に更新します。 組織が必要とする場合にのみ、顧客が管理する証明書を使用してください。

## 顧客管理の証明書を使用する場合

* **ファーストパーティのオリジンを持つCDNを介してデータ収集をルーティングします**:[Adobeで管理されている証明書プログラム ](adobe-managed-cert.md)は、CDN実装をサポートしていません。 [ ファーストパーティのオリジンを使用したCDNの設定](cdn.md#first-party-origin)を参照してください。
* **セキュリティポリシーでは、証明書を直接管理する必要があります**。例えば、Adobe カスタマーケアを通じて失効を要求する代わりに、独自の証明機関を通じて証明書を失効させることができなければなりません。
* **お客様の組織では、特定の証明機関または証明書の種類**&#x200B;が必要です。Adobeで管理されている証明書プログラムでは、DigiCertが発行した証明書を使用しています。

## 証明書メソッドの比較

| | アドビ管理の証明書 | 顧客管理の証明書 |
| --- | --- | --- |
| **証明書を取得したユーザー** | Adobe、DigiCert経由 | お客様の組織は、選択した商業認証局を通じて |
| **更新** | Adobeは、証明書を自動的に更新します | 組織は証明書を更新し、有効期限が切れるたびにAdobeに提供します |
| **証明書の種類** | Adobeには、RSA証明書とECC証明書の両方が用意されています | RSAが必要です。ECCが推奨されます |
| **CDN**&#x200B;でサポートされています | × | はい、1st パーティオリジンとして |

## 顧客管理の証明書の設定

1. お客様が管理する証明書によるファーストパーティデータの収集をリクエストするには、Adobe カスタマーケアにお問い合わせください。 `data.example.com`などの1st パーティホスト名を含めます。 組織にデータレジデンシーまたはコンプライアンス要件がある場合は、リクエストに目的の[RDC タイプ ](rdc.md)を指定します。
1. Adobe カスタマーケアは、ホスト名に対する証明書署名リクエスト（CSR）を提供します。 Adobeは秘密鍵を生成して保持するので、組織が秘密鍵を処理することはありません。 AdobeにはRSA証明書が必要で、ECC証明書を推奨します。 証明書の種類ごとに独自のCSRが必要となるので、ECC証明書が必要な場合は、Adobe カスタマーケアにECC CSRの入力を依頼してください。
1. 署名済み証明書を取得するには、各CSRを目的の商用証明機関に送信します。 無料の証明書サービスはサポートされていません。 カスタマーケアの指示に従って、発行された証明書をAdobeに提供します。
1. Adobeが証明書をインストールしたら、ホスト名のトラフィックをAdobeに転送します。
   * **CDNなし**:Adobe カスタマーケアの指示に従って、組織のDNS レコードを更新します。
   * **CDNを使用**: CDN オリジンをファーストパーティホスト名に設定します。 [ ファーストパーティのオリジンを使用したCDNの設定](cdn.md#first-party-origin)を参照してください。
1. 実装がこのホスト名にデータをまだ送信していない場合は、[実装を更新してください](collection-domain.md#update-implementation)。

## 証明書を更新 {#renewals}

お客様の組織は、現在の証明書が期限切れになる前に、証明書を更新し、更新した証明書をAdobe カスタマーケアに提供する責任があります。

Adobe サーバー上の証明書の有効期限が切れると、ブラウザーとCDNはホスト名への接続を拒否し、それらのリクエストのデータは失われます。 CDNは、ユーザーに通知せずにこのデータを破棄できます。

証明書の最大有効期間が短くなっているため、更新の頻度が低下しています。 詳しくは、「CA/Browser Forum Server Certificate Baseline Requirements」の「[6.3.2証明書の運用期間とキーペアの使用期間](https://cabforum.org/working-groups/server/baseline-requirements/requirements/#632-certificate-operational-periods-and-key-pair-usage-periods)」を参照してください。 データ収集のギャップを回避するには、次の手順に従います。

* Adobeに提供する各証明書の有効期限を追跡します。
* 更新に所有者を割り当て、更新プロセスを文書化して、スタッフの変更を継続します。

Adobeは現在、セルフサービス証明書の更新プロセスを検討中です。

## 顧客管理の証明書の使用を停止する

* **Adobeが管理する証明書プログラムに移行するには**: Adobe カスタマーケアにお問い合わせください。 Adobeで管理される証明書プログラムでは、ホスト名がCDNではなくAdobeを直接指している必要があります。
* **ファーストパーティのホスト名の使用を停止するには**: ホスト名を使用するすべての実装を更新してから、Adobe カスタマーケアに連絡して、Adobe サーバーから証明書を削除してください。
* **サードパーティのオリジンを持つCDNに移行するには**: [既存のファーストパーティ実装をCDNに移行](cdn.md#migrate)を参照してください。
